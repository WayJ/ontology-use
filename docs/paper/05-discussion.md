# 5. 讨论

## 5.1 第一期能说明什么

- **管道可用：** 默认评测全员 1.0 / 0 failures（§4.2，16 任务）表明 pack 加载、方法注册、打分与写表闭环成立。
- **捷径可关：** 严格模式全员 0.0（§4.3）表明 `strictMock` 生效，结果目录分离（`results/` vs `results/strict/`），避免污染烟测表。
- **真实 LLM 可对照：** MiniMax-M3.1-Flash 调优跑（`results/llm-20261029T231459/`，§4.4）给出方法间差异：M0/M10 最高（0.9375），M6 最低（0.1250）；均分约 0.54。对外能力结论**只**引用该表（或后续新 `results/llm-*/`），**禁止**用 mock 1.0 表排名。

## 5.2 方法设计取舍

- M0/M1 成本低、上下文易爆或信息不足；M2–M4 引入检索假设；M5–M7 强调工具与校验；M8–M10 对齐业界「taxonomy / 治理写回 / Action」叙事但保持无私有 SDK。
- 本轮 LLM 上 PromptDump（M0）与 ActionSDK 风格（M10）并列领先，SHACLGate（M6）最弱——与「先生成再门控」在短题集、紧输出契约下易漏过金标格式一致；不宜外推为 SHACL 无效，更可能是门控与解析/重试策略未调优。
- 迷你包任务偏 IRI 精确匹配与集合 F1，对开放文本生成不友好——这是刻意选择，便于自动评测。

## 5.3 威胁效度

- 任务仍少（当前默认 **16** = mini 7 + foaf-lite 5 + org-lite 4）、本体小，外推有限；单模型、单次跑，不作跨厂商泛化。
- mock-shortcut 若被误读为模型分数，会严重误导；论文与 README 需重复警示。
- 旧跑 `llm-20261029T222608/`（调优前多数 ≈0–0.125）不可与调优表混用。
- M8–M10 仅为风格桩，不等于复现 Planeteer / Onto Planet / OSDK 产品行为。
- 成本：本轮 `meta.json` 合计约 12.3 万 tokens；延迟与按方法拆分成本尚未成表（§4.5）。
